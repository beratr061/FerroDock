# ADR 0001: Foundation architecture

Status: accepted, 2026-11-25

## Context

Dokploy proves the product shape (project, environment, service; Git builds; Traefik routing; live logs; managed databases; backups) but its Node.js monolith idles around 500 MiB plus swap, requires Docker Swarm, runs a separate Go monitoring service, has no i18n and builds commands as shell strings. FerroDock rebuilds the same product logic with a small, secure and maintainable core.

## Decisions

- **Runtime**: Rust (axum, tokio) as a single binary that also serves the embedded React SPA.
- **Orchestration**: plain Docker Engine and Compose. Swarm is not required; zero-downtime deploys use a blue-green switch behind Traefik, with a Recreate strategy for workloads with writable mounts.
- **Database**: PostgreSQL first, no Redis. Queries are compile-time checked with sqlx and live only in engine-specific modules behind repository traits, so a SQLite driver can be added later. The job queue is a separate trait (Postgres: `SKIP LOCKED` plus `LISTEN/NOTIFY`).
- **Proxy**: Traefik v3 with the file provider; one typed, atomically written file per service.
- **Remote servers**: agentless, one pooled `russh` connection per server carrying Docker API (streamlocal), PTY and SFTP, with TOFU host key pinning.
- **API**: REST under `/api/v1` with an OpenAPI 3.1 contract generated by utoipa; frontend types are generated from it.
- **Crates**: `core`, `db`, `domain`, `api`, `ferrodock` today; `infra`, `engine` and `realtime` join as their phases start. Dependencies point one way and HTTP lives only in `api`.
- **Security**: Argon2id, opaque session tokens stored as hashes, HttpOnly cookies, scoped API keys, CSRF origin checks, rate limiting, security headers, AES-256-GCM for stored secrets, no secrets in process arguments, no shell string interpolation.
- **Frontend**: React 19, Vite, Tailwind v4 with opaque neutral tokens (WCAG AA minimum, AAA for primary text), Poppins and JetBrains Mono, TanStack Router and Query, i18next with languages discovered from `web/locales`.
- **Updates**: signed release manifests with image digests, automatic backup before update, health-gated switch through a short-lived updater container, automatic rollback, expand/contract migrations.

## Phases

0. Foundation: workspace, auth, API contract, SPA shell, image, installer, CI.
1. Core PaaS: Docker integration, durable job queue, Git and image sources, Dockerfile and Compose deploys, blue-green and recreate strategies, rollback, image pruning, Traefik domains with DNS pre-checks and Let's Encrypt, encrypted environment variables, WebSocket hub, basic terminal, panel backup, one-click update. When xterm.js and CodeMirror land, `style-src` gains a per-response nonce for the style elements they inject (not `unsafe-inline`); same-origin WebSockets are already covered by `connect-src 'self'`.
2. Terminal, managed databases, backups and restore.
3. Remote servers, metrics, webhooks, preview deployments, notifications, schedules.
4. Hardening and v1.0: TOTP, audit log UI, Nixpacks, Railpack and static builders, SQLite driver, Dokploy import, CLI.
